# 产出模板

两份交付物都是 `.docx`,遵循 docx 技能的约定。本文件给出共享样式规范和一个现成
生成器,让每次产出风格一致。

---

## 共享样式规范

- 字体:`Microsoft YaHei`(CJK 通用)。默认字号 11pt。
- 页面:US Letter,1 英寸页边距(宽 12240 / 高 15840 DXA)。
- 标题:H1 字号 15pt 加粗 颜色 `2E5496`;H2 字号 12.5pt 加粗 颜色 `1F3864`。
- 大标题:字号 20pt 加粗 颜色 `1F3864`。
- 表格:表头行填充 `2E5496` 白字加粗;标签格填充 `EAF0F8`;边框 `CCCCCC`;
  单元格内边距 `{top:80,bottom:80,left:120,right:120}`;宽度用 DXA 合计 9360;
  `columnWidths` 和每个单元格 `width` 都要设;用 `ShadingType.CLEAR`。
- 关键结论强调:加粗 + 颜色 `C00000`,少用。
- 列表用真正的编号配置(绝不用 unicode 项目符号)。

生成后校验:`python /mnt/skills/public/docx/scripts/office/validate.py <文件>`

## 要产出的两份文档

### A. 复盘文档
结构:
1. 大标题 + 一行元信息(公司 / 轮次 / 面试官类型 / 日期)。
2. **本场定性** — 轮次类型、强度、以及任何 JD 与实际岗位的错配。
3. **逐题解码** — 每题:维度 / 潜台词 / 站得住的答法(用 feedback-method.md 的
   逐题结构)。可用表格,或每题一个 H2。
4. **做得好的地方** — 真实的强项,引用面试官原话。
5. **问题诊断(三层)** — 三层模型,以及对照历史档案的复发情况。
6. **下一场针对性练习计划** — 排好优先级,带具体训练动作。

### B. 档案文档(活看板)
结构:
1. 大标题 + 「最近更新」日期。
2. **一句话总根** — 候选人的核心总根模式。
3. **三层问题 + 复发计数** — 表格:层 / 模式 / 状态(新/复发×N/改善中/已稳定)。
4. **正在改善 / 已稳定** — 哪些在变好。
5. **随身工具** — 他的起手式和训练动作。
6. **面试日志** — 每场一行:日期 / 公司 / 轮次 / 头条发现。

## 现成生成器脚本

`scripts/make_docx.py` 读一个 JSON 规格、输出排好版的 .docx,这样你不用每次
手写 docx 代码。它支持大标题、元信息、各级标题、段落(可选强调)、项目符号/
编号列表、表格。用法:

```bash
cd <技能目录>
python scripts/make_docx.py spec.json /mnt/user-data/outputs/复盘.docx
```

`spec.json` 形如:
```json
{
  "title": "面试复盘 · 某公司数据分析岗",
  "meta": "用人团队负责人面 · 2026-06-01",
  "blocks": [
    {"type": "h1", "text": "一、本场定性"},
    {"type": "p", "text": "这是一轮实习留用的第一面……"},
    {"type": "p", "text": "关键结论", "emphasis": true},
    {"type": "num", "items": ["先练开口前半秒", "背死三个起手式", "练承接"]},
    {"type": "table",
     "header": ["维度", "信号词", "答题落点"],
     "widths": [1500, 2700, 5160],
     "rows": [["权衡判断", "哪个更重要", "先下判断,依据用破坏力"]]}
  ]
}
```

脚本刻意做得简单;若排版需求超出它(图片、嵌套列表),按 docx 技能直接写
docx 代码兜底。依赖:`pip install python-docx --break-system-packages`。
